## 1. Headline

**PartCraft already has most of the NURBS geometry the plan was going to write.** It also has a STEP B-rep evaluator and
an ACIS reader. The plan assumed a blank slate (S4–S10 from scratch, a separate repository), and that is wrong.

PartCore's real job is the layer PartCraft does not have: **exact B-rep topology.** That means:
- edges that are shared, exact curves with pcurves on both faces
- trims that are exact curves rather than polygons
- solids that are valid by construction and checked by an independent auditor
- STEP written with exact edge curves
- no mesh booleans

So the plan keeps its architecture, numerics, topology, audit and roadmap shape, but it is rebased onto cc-nurbs,
cc-step and cc-acis, and it lives in this repository under `app/partcore/`. The details are in §5.

## 2. What PartCraft already has (S0 audit)

All of it is DOM-free and Apache-2.0, written from published sources (each file cites them), and in the same style as
the plan: untrusted input checked, errors as codes, reports that state measured deviations.

**Health:**
- **`tests/tools/nurbs/test.mjs`: 173 passed, 1 failed.** The one failure is "ModelCraft and PartCraft copies
  byte-identical (sync --check)", which needs the CadCraft monorepo layout, not this fork.
- `test-trim.mjs`: 25 of 25 passed.
- `test-solid.mjs` needs the vendored manifold-3d, so it was not run here.

**Constraint:** cc-nurbs is canonical in the monorepo's `lib/nurbs`, and ModelCraft and PartCraft carry byte-identical
copies (`tools/nurbs/sync.mjs`). So **PartCore must not edit `app/nurbs/` in place.** It imports it, and any fix it needs
goes to the canonical copy upstream (decision D-ccn).

### 2.2 cc-step — `app/step/`

- **`read.js`** reads AP203 / AP214 / AP242 B-reps, faceted B-reps and AP242 tessellated faces, with assembly placement.
  The output is **triangles**: `positions`, `indices` and `triFace` per solid, plus notes and counts.
- **`geom.js`** evaluates *and inverts* the STEP geometry entities: line, circle, ellipse, polyline, B-spline, plane,
  cylinder, cone, sphere, torus, revolution, extrusion and offset surfaces. It handles periods, poles and per-direction
  scale.
- **`tess.js`** discretises each edge once, shared by its two faces, so shells stay closed. Faces are triangulated in
  (u, v), with periodic directions unwrapped and poles split, by ear clipping plus Delaunay flips.
- **`part21.js`** is a one-pass ISO 10303-21 index plus a lazy parameter parser (complex instances included).
- **Covers:** S28 (parser: done), most of S30's geometry (evaluators: done), and S15–S16's ideas (shared edges, seams and
  poles). What PartCore adds is building B-rep *topology* instead of triangles.

### 2.3 cc-acis — `tests/lib/acis/` (test copy of the monorepo's `lib/acis`; not in `app/`)

- SAT / SAB → topology and geometry, by ACIS version.
- Planes, cones, cylinders, spheres, tori and B-spline `exactsur` surfaces.
- Edges: lines, ellipses and B-spline `intcurve`s.
- Its own **constrained Delaunay triangulation (`cdt.js`)** and a tessellator that handles seams and poles.
- **S33 shrinks** from "write a SAT reader" to "lift cc-acis' model into PartCore topology". `cdt.js` is the first candidate
  for S16.

### 2.4 The rest of PartCraft that matters here

- `kernel.js`: the manifold mesh kernel that builds every part today.
- `brep*.js` and `exact-client.js`: the OpenCascade route, opt-in and absent from builds since 0.4 for licensing.
  `ExactKernel` starts `brep-worker.js` and is called as `k.call('regen', { part })`. That message protocol is the seam
  PartCore plugs into (S36).
- `sketch*.js`: PartCraft's sketcher (arcs, intersections, splines). Not read in this review.
- `cam-*.js`: PartCraft already has a CAM stack. From the file names it covers adaptive clearing, offsets, finishing,
  cycles, posts and a post editor, simulation and tool tables. Not read in this review.
- `PROVENANCE.md`: "Features that need an exact B-rep kernel say 'Not built yet'". PartCore is what turns those on.

## 3. Changes to the plan (applied in `HANDOFF.md` v1.1)

| # | Plan v1.0 said | v1.1 says | Why |
|---|---|---|---|
| P1 | Separate repository `withshalom/knot` (D-repo) | **In this repository**: `app/partcore/` (DOM-free, like `app/nurbs/`), tests in `tests/tools/partcore/`, run by `tests/bin/test-partcore.mjs` so `npm test` includes them; docs in `docs/partcore/`; work on branch `partcore` | the owner's direction; PartCraft is the first consumer |
| P2 | M1 (S4–S10) builds NURBS from scratch | M1 becomes **adopt cc-nurbs**: S4–S10 shrink to wrappers, missing pieces (analytic classes, exact conversions, interval tools) and PartCore-side tests | §2.1 |
| P3 | Float64Array struct-of-arrays representation | cc-nurbs plain data `{ deg, knots, cvs, w }` at every boundary; typed arrays only inside hot loops, when a benchmark asks for them | interoperate with cc-nurbs without converting |
| P4 | Errors: an `EngineError` class | **`partcore.err.*` codes in cc-nurbs' style** (a code the app words through i18n, plus details) | PartCraft convention |
| P5 | S13 trims from scratch | S13 adds **exact pcurve trims** next to cc-nurbs' polygon trims, which stay for display | §2.1 `trim.js` |
| P6 | S16 constrained Delaunay from scratch | S16 starts from cc-acis `cdt.js` and cc-step `tess.js` | §2.2, §2.3 |
| P7 | S28 Part 21 parser from scratch | **S28 is done** (`app/step/part21.js`); the session becomes limits plus fuzzing of that parser | §2.2 |
| P8 | S29 writer from scratch | S29 extends cc-nurbs `step.js`, which already writes `MANIFOLD_SOLID_BREP`: exact edge curves (`LINE`, `CIRCLE`, `B_SPLINE_CURVE_WITH_KNOTS`) and analytic surfaces instead of `POLYLINE` edges | §2.1 |
| P9 | S30 reader from scratch | S30 builds PartCore topology from cc-step's instance index and `geom.js` evaluators | §2.2 |
| P10 | S33 ACIS reader from scratch (optional) | S33 lifts cc-acis' model into PartCore topology | §2.3 |
| P14 | D3 "no booleans" interpretation | Unchanged, and now concrete: PartCore's core never calls `solid.boolean` or manifold. cc-nurbs' mesh booleans and `blend.fillet` stay available to PartCraft as the mesh route, outside PartCore | §2.1 |
| P15 | Licence: dual MIT / Apache-2.0 headers suggested | Files in this repository use PartCraft's `Apache-2.0` header. | consistency with `LICENSE` / `NOTICE` |
| P16 | Session protocol: "never push without go-ahead" | Unchanged. Pushing `knot/*` branches was approved for this setup; `main` is not touched by kernel sessions without a pull request | — |
